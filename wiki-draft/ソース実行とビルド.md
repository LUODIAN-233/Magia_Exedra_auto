# ソース実行とビルド

言語：[简体中文](./首页) · [English](./Home_EN) · [日本語](./ホーム)

## 実行環境

- OS：Windows x86-64 / AMD64
- Python：3.x（3.10 以上を推奨）

## 依存関係のインストール

実行時依存関係は `requirements.txt` に宣言されています：

```bash
pip install -r requirements.txt
```

リリースビルドでは `requirements-build.txt` を使用します。実行時依存関係に加えて、検証済みの PyInstaller 6.21.0 が固定されています：

```bash
pip install -r requirements-build.txt
```

素材のスケーリングはリポジトリ内にコミットされた `tools/ImageMagick/magick.exe` を使用し、別途インストールは不要です。PATH 上の `magick` も利用可能です。

## ソースからの実行

```bash
python main.py
```

`main.py` がエントリポイントです。起動時にカレントディレクトリをスクリプト配置ディレクトリに切り替え、相対実行時パス（`./aim/...`、`./resource/...`）が正しく解決されるようにします。起動時に `language_switcher.ensure_active()` が呼ばれ、`aim/` ディレクトリジャンクションを復元または作成します。

起動時に `log_setup.configure_logging()` も呼ばれます。GUI では DEBUG / INFO / WARNING / ERROR / CRITICAL を選択でき、新規インストールは INFO がデフォルトです。この選択は GUI のデバッグ記録と `logs/` のファイルに同時に適用されます。ログはデフォルトで7日間保持され、1～365日に変更でき、起動時に自動削除されます。ソース実行時のコンソールはデフォルトで WARNING 以上のみを出力し、`MAGIA_LOG_LEVEL=DEBUG` ですべてのコンソール出力を表示できます。

## パッケージ化

PyInstaller の onedir モードを使用します：

```bash
pyinstaller -D --windowed -i resource/main.ico -n Magia_Exedra_auto main.py
```

`--windowed` により、GUI と一緒に空のコンソールウィンドウが表示されるのを防ぎます。旧 console モードの frozen ビルドにも互換性があり、起動時に既存のコンソールを非表示にします。`-n Magia_Exedra_auto` はビルドされたエントリ exe をプロジェクト名 `Magia_Exedra_auto.exe`（デフォルトの `main.exe` ではなく）に命名します。これがリリースで実際に使用されるエントリ実行ファイルです。このコマンドは PyInstaller の onedir 出力（`dist/Magia_Exedra_auto/` に `Magia_Exedra_auto.exe` と `_internal/` を含む）のみを生成します。配布可能なパッケージには、`Magia_Exedra_auto.exe` と同階層にバージョン管理された実行時ファイルも配置する必要があります：

- `resource/`（アイコン等のリソース）
- `language/`（テンプレート pack、`.gitkeep` プレースホルダを含む）
- `tools/`（ImageMagick 実行ファイル）

`Magia_Exedra_auto.exe` は ZIP のルートに配置してください。`aim/`、`active.json`、`.source_hashes.json`、ローカル生成の派生テンプレート、キャッシュ、Git/ビルドメタデータはリリースパッケージに含めないでください。

## パッケージ化の注意事項

- frozen モードでは、`cv2` がインポートされる前に環境変数 `OPENCV_SKIP_PYTHON_LOADER=1` を設定する必要があります。`main.py` がエントリポイントで処理していますが、インポート順序を変えないでください。
- **DPI に敏感なインポート順序**：`src.workers` は遅延インポートのままにしてください。起動は `QApplication(...) -> mywindow() -> get_worker_registry()` の順序を維持する必要があります。workers を先にインポートすると PyAutoGUI が読み込まれ、Qt が Windows DPI awareness を設定できなくなる可能性があります。`main.py` はモジュールインポート時に `QApplication` の前に `log_setup.configure_logging()` を呼び出します。このモジュールは標準ライブラリのみに依存し安全で、すべての logger を確実にキャプチャするためビジネスモジュールのインポートより先に実行する必要があります。

## 検証チェック

標準ライブラリの回帰テストは `tests/` にあります。lint と CI の設定はまだありません。変更後は該当する非ゲームチェックを実行してください：

- `python -B -m unittest discover -s tests -v`
- Python コンパイル/インポートチェック
- worker レジストリとテンプレート検証
- 更新 ZIP/展開チェック
- ロック/アップデータチェック
- AMD64 PE 検証
- パッケージ化後のスモークスタート
